# ทำเอกสารและไฟล์ PDF — กฎกลาง ใช้ได้ทุกโปรเจกต์

> ตั้งขึ้น **26 สิงหาคม 2569** ตามที่พี่กันสั่ง: *"ตั้งเป็นกฎเลย ถ้าเป็นการสร้างไฟล์ ต้องดูของจริง"*
> และ *"ตั้งระบบนี้เป็นสกิลกลางด้วย"*
>
> เกิดจากงานใบสรุป Lot ของเว็บมูลค่ายาคืน ที่ต้องแก้ 6 รอบกว่าจะออกมาถูก
> ทุกข้อในนี้คือบั๊กที่เจอจริง ไม่ใช่ทฤษฎี

## 🔴 กฎข้อที่ 1 — สร้างไฟล์ ต้องเปิดไฟล์จริงดู

**ห้ามจำลอง ห้ามเดา ห้ามดูแค่หน้าจอแล้วสรุปว่าไฟล์จะออกมาแบบนั้น**

พี่กันย้ำ 3 รอบในวันเดียว: *"อย่าจำลอง ถ้าจำลองก็ไม่เห็นของจริงสิ"* · *"ห้ามจำลองงงงงง"*
· *"แค่เอกสารราชการ ทำออกมาจนกว่าจะดี เทสทุกครั้ง"*

### ทำไมดูหน้าจอไม่พอ

| สิ่งที่เห็นบนจอ | สิ่งที่ออกมาในไฟล์จริง |
|---|---|
| ตัวหนังสือขนาดพอดี | เล็กจิ๋ว (สไตล์ฝังในแท็กหน่วย px ชนะกฎ CSS พิมพ์) |
| ฟอนต์ที่ตั้งไว้ | ฟอนต์สำรองของระบบ (เบราว์เซอร์ไม่โหลดฟอนต์ที่ไม่มีอะไรใช้) |
| ใบสรุปใบเดียว | หน้าเว็บทั้งหน้า พร้อมปุ่มทุกปุ่ม |
| กระดาษขาวสะอาด | มีแถบเทาก้นกระดาษ (พื้นหลังเว็บโผล่) |

ทั้ง 4 แถวนี้เกิดขึ้นจริงในงานเดียว และ**ไม่มีอันไหนมองเห็นได้จากหน้าจอเลย**

### เครื่องมือที่ต้องมีในทุกโปรเจกต์ที่สร้างไฟล์

ต้นแบบอยู่ที่ `C:\Users\PKH\Returned-Drug-Value\scripts\`

| ไฟล์ | ทำอะไร |
|---|---|
| `print-check.mjs` | สั่ง Chrome ในเครื่องสร้าง PDF จริงจากเว็บที่รันอยู่ |
| `pdf-look.mjs` | แปลงหน้า PDF เป็นภาพ เพื่อเปิดดูด้วยตา |
| `pdf-font.mjs` | คลายก้อนบีบอัดในไฟล์ PDF อ่านว่าฝังฟอนต์อะไรมาจริง |
| `ui-check.mjs` | ถ่ายภาพหน้าเว็บจริง + รายงานข้อผิดพลาดในคอนโซล |

**ทุกครั้งที่แก้เอกสาร ต้องรันซ้ำแล้วเปิดภาพดู** ไม่ใช่แก้แล้วบอกว่าน่าจะดีขึ้น

```bash
node scripts/print-check.mjs && node scripts/pdf-look.mjs out/ไฟล์.pdf
```

### เครื่องนี้อ่าน PDF ตรง ๆ ไม่ได้

ไม่มี poppler → เครื่องมืออ่าน PDF ในตัวใช้ไม่ได้
ต้องแปลงเป็นภาพก่อนด้วย `pdf-to-img` (ลงผ่าน `npm i -D pdf-to-img`)

## 🔴 กฎข้อที่ 2 — ทำกระดาษให้เป็นกระดาษจริงตั้งแต่บนหน้าจอ

**อย่าทำเว็บสวย ๆ แล้วหวังว่ากฎ `@media print` จะแปลงให้เป็นเอกสารตอนพิมพ์**

ทางนั้นล้มเหลวเสมอ เพราะสไตล์ที่เขียนฝังในแท็ก (`style="..."`) **ชนะกฎในไฟล์ CSS ทุกกรณี**
ต่อให้ใส่ `!important` ก็ไล่ทับไม่ครบทุกจุด

### ท่าที่ถูก (ยกมาจากโปรเจกต์ listless ที่ทำไว้ดีแล้ว)

```css
.slip-paper {
  width: 210mm;              /* กว้างเท่ากระดาษ A4 จริง */
  min-height: 287mm;         /* สูงเท่ากระดาษ ลบขอบบนล่างแล้ว */
  padding: 16mm;             /* ขอบกระดาษ */
  font-family: "TH Sarabun New", sans-serif;
  font-size: 16pt;           /* 🚨 pt ไม่ใช่ px */
  background: #fff;
  color: #000;
}
```

**ทุกขนาดในเอกสารใช้หน่วย `pt` กับ `mm` เท่านั้น**
`px` ผูกกับหน้าจอซึ่งไม่มีความหมายบนกระดาษ · `pt` กับ `mm` ผูกกับกระดาษจริง

**ในกระดาษห้ามมีสไตล์ฝังในแท็กแม้แต่จุดเดียว** ใช้คลาสล้วน
สิ่งที่เห็นบนจอจะได้เท่ากับสิ่งที่ออกมาบนกระดาษเป๊ะ ไม่ต้องเดา

```css
@page { size: A4 portrait; margin: 16mm; }
```

## 🔴 กฎข้อที่ 3 — เอกสารต้องแขวนไว้ที่ `body` โดยตรง

**อาการ:** กด Ctrl+P แล้วได้หน้าเว็บทั้งหน้าออกมา มีปุ่มทุกปุ่มติดไปในกระดาษ

**ต้นเหตุ:** กฎซ่อนที่เขียนกันบ่อย

```css
body > * { display: none !important; }
body > div:has(.กระดาษ) { display: block !important; }   /* ❌ */
```

เครื่องมือสร้างเว็บสมัยใหม่ (Next.js · Nuxt · SvelteKit) **ห่อทั้งเว็บไว้ในกล่องเดียว**
ตัวเลือกบรรทัดที่สองจึงไปตรงกับกล่องที่ครอบทั้งเว็บ แล้วเปิดกลับมาทั้งหน้า

**วิธีแก้ที่ถูก — ย้ายเอกสารไปแขวนที่ `body` ด้วย portal**

```jsx
// React
if (typeof document === 'undefined') return null;   // กันตอนเซิร์ฟเวอร์วาดจอ
return createPortal(sheet, document.body);
```

```css
body > * { display: none !important; }
body > .กล่องเอกสาร { display: block !important; }   /* ✅ ตรงกับตัวจริงแน่นอน */
html, body { background: #fff !important; }          /* 🚨 กันแถบเทาก้นกระดาษ */
```

🚨 **ใช้ `display: none` ไม่ใช่ `visibility: hidden`** — ของที่ซ่อนด้วย visibility ยังกินที่อยู่
จะได้กระดาษเปล่านำหน้าหลายแผ่นก่อนถึงใบจริง

## 🔴 กฎข้อที่ 4 — ฟอนต์ต้องสั่งให้โหลดก่อนพิมพ์

**เบราว์เซอร์โหลดฟอนต์เฉพาะเมื่อมีอะไรบนหน้ากำลังใช้มันอยู่**
เอกสารที่เพิ่งเปิดขึ้นมาแล้วสั่งพิมพ์ทันที = ฟอนต์ยังโหลดไม่เสร็จ = ได้ฟอนต์สำรอง

```js
await Promise.all([
  document.fonts.load('16pt "TH Sarabun New"'),
  document.fonts.load('700 16pt "TH Sarabun New"')   // 🚨 ตัวหนาต้องสั่งแยก
]);
```

**ตรวจว่าได้ฟอนต์จริงไหม อ่านจากไฟล์เท่านั้น** (`pdf-font.mjs`)
ผลที่ถูกต้องจะเห็นแบบนี้

```
BaseFont: AAAAAA+THSarabunNew-Bold
BaseFont: BAAAAA+THSarabunNew
```

## 📜 เอกสารราชการไทย — สิ่งที่ต้องมี

### รูปแบบ

| เรื่อง | กติกา |
|---|---|
| สี | **ขาวดำ** พื้นเทาอ่อนได้เฉพาะหัวตารางกับแถวยอดรวม ห้ามใช้สีสด |
| ฟอนต์ | **TH Sarabun New** (ฟอนต์ราชการ) ไม่ใช่ Sarabun ของ Google ซึ่งคนละตัว |
| ขนาด | เนื้อความ 16 pt · หัวเรื่อง 22 pt · ชื่อหน่วยงาน 17 pt · ตาราง 14 pt |
| ตาราง | **มีเส้นกรอบครบทุกด้าน** ไม่ใช่เส้นคั่นแนวนอนอย่างเดียวแบบเว็บ |
| วันที่ | **เดือนเต็ม + พ.ศ.** เช่น `26 สิงหาคม พ.ศ. 2569` ห้ามใช้ตัวย่อ |
| ชื่อหน่วยงาน | **ชื่อเต็มตามทะเบียน** ไม่ใช่ชื่อสั้นที่เรียกกันในที่ทำงาน |

### ส่วนประกอบ

```
        ชื่อหน่วยงานเต็มยศ (กึ่งกลาง)
           ชื่อเอกสาร (ตัวใหญ่ กึ่งกลาง)

เลขที่เอกสาร ...          แหล่งที่มา ...
วันที่ ...                จำนวนรายการ ...
ผู้บันทึก ...

[ตารางรายการ มีเส้นกรอบครบ]
[แถวยอดรวมท้ายตาราง]

[ช่องลงนาม 3 ฝ่าย: ผู้ปฏิบัติ · ผู้รับผิดชอบ · ผู้ตรวจสอบ]
```

🚨 **ห้ามใส่ข้อมูลเดียวกันสองที่** — เลขที่เอกสารที่สร้างจากเลขอ้างอิงภายในแล้ว
ไม่ต้องมีบรรทัดเลขอ้างอิงซ้ำอีก (พี่กันจับได้ทันที: *"มันซ้ำกันไหม"*)

🚨 **ช่องลงนามห้ามยุบให้น้อยกว่าที่ควรมี** — ผู้ปฏิบัติกับผู้ตรวจสอบเป็นคนละบทบาท
เอกสารที่ต้องส่งตรวจต้องมีครบ

### ข้อความยาวต้องได้บรรทัดเต็ม

ชื่อหน่วยงานเต็มตามทะเบียนยาวเกินครึ่งกระดาษ
ยัดลงคอลัมน์ในหัวเอกสารแล้ว**ตกบรรทัด ดันบรรทัดอื่นเลื่อนตาม จนสองฝั่งไม่ตรงกัน**
→ ให้เป็นบรรทัดของตัวเองเต็มความกว้าง

## 📄 ตารางที่ไหลข้ามหน้า

```css
.ตาราง { page-break-inside: auto; }
.ตาราง thead { display: table-header-group; }   /* หัวตารางซ้ำทุกหน้า */
.ตาราง tr { page-break-inside: avoid; }         /* ไม่ตัดกลางแถว */
.ช่องลงนาม { break-inside: avoid; }             /* ไม่ตกไปอยู่หน้าใหม่ลำพัง */
```

🚨 **ล็อกความกว้างคอลัมน์ด้วย `table-layout: fixed` + `<colgroup>`**
ไม่งั้นข้อความยาว ๆ ในคอลัมน์เดียวจะดันคอลัมน์ตัวเลขจนบี้

🚨 **ห้ามตัดจำนวนแถวเงียบ ๆ** — เอกสารที่มี 80 รายการแต่พิมพ์ออกมา 60
ยอดท้ายใบจะไม่ตรงกับที่เห็นบนจอ และไม่มีอะไรเตือนเลย

## 🖨 สร้าง PDF — ใช้ตัวแปลงของเบราว์เซอร์

**อย่าลงไลบรารีสร้าง PDF ฝั่งจาวาสคริปต์** (jsPDF · pdfmake) สำหรับงานเอกสารไทย

| เหตุผล | รายละเอียด |
|---|---|
| น้ำหนัก | ต้องฝังฟอนต์ไทยเข้าไปเอง ชุดละ ~300 KB · 5 น้ำหนัก = 1.5 MB ถ่วงทั้งเว็บ |
| สระวรรณยุกต์ | มักลอยผิดตำแหน่งในตัวสร้าง PDF ฝั่งจาวาสคริปต์ |
| ความตรง | ตัวแปลงของเบราว์เซอร์ใช้ฟอนต์ที่หน้าเว็บใช้อยู่แล้ว จึงตรงเป๊ะ 100% |

**ปุ่ม "บันทึก PDF" ทำได้ด้วยการตั้งชื่อหน้าเว็บชั่วคราวแล้วสั่งพิมพ์**
(เบราว์เซอร์ตั้งชื่อไฟล์ PDF จากชื่อหน้าเว็บ)

🚨 **สั่งพิมพ์ต้องรอ 2 เฟรมหลังข้อมูลมาถึง** ไม่งั้นได้กระดาษเปล่า

## ✅ รายการตรวจก่อนบอกว่าเสร็จ

- [ ] รันตัวสร้างไฟล์แล้ว **เปิดไฟล์จริงดูด้วยตา**
- [ ] ฟอนต์ในไฟล์เป็นตัวที่ตั้งใจ (ตรวจจากไฟล์ ไม่ใช่จากหน้าจอ)
- [ ] ได้เฉพาะเอกสาร ไม่มีส่วนของหน้าเว็บติดมา
- [ ] ไม่มีแถบสีแปลกปลอมที่ขอบหรือก้นกระดาษ
- [ ] วันที่เป็นเดือนเต็ม + พ.ศ.
- [ ] ไม่มีข้อมูลซ้ำสองที่
- [ ] ข้อความยาวไม่ตกบรรทัดจนดันของอื่นเลื่อน
- [ ] เอกสารหลายหน้า — หัวตารางซ้ำทุกหน้า ช่องลงนามไม่ตกหน้าใหม่ลำพัง
- [ ] จำนวนแถวในไฟล์เท่ากับที่เห็นบนจอ ยอดรวมตรงกัน

## 🔴 เอกสารที่พิมพ์ออกกระดาษ ต้องมีค่าเดียวต่อช่องเสมอ

**หน้าเว็บแสดงหลายค่าในช่องเดียวได้** (เช่น `เลขที่ 22, 23` เมื่อมีข้อมูลขัดกัน)
**แต่เอกสารราชการที่พิมพ์ออกไปทำแบบนั้นไม่ได้**

> *"การพิมพ์ `เลขที่ 22, 23` ลงแบบฟอร์มราชการ อ่านแล้วเหมือนเอกสารเสีย"*

🚨 **ตัวสร้างเอกสารต้องเลือกค่าเดียวมาใช้ และแก้ข้อมูลที่ขัดกันให้จบก่อนพิมพ์**
ห้ามใช้ตัวช่วยที่แสดงหลายค่าแบบเดียวกับบนหน้าจอ
