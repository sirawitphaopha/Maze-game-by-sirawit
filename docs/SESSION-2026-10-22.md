## สิ่งที่เรียนรู้ (อ่านก่อนแตะหน้าเล่นเกมมือถือ)

- **หน้าเล่นเกมสูงตายตัวแล้ว** (`.play` height) อะไรที่แทรกเข้าลำดับหน้าจะทำให้ปุ่มหดแทนที่จะดันลง · ข้อความใหม่ต้องลอยทับหรืออยู่ในที่ที่จองไว้
- **หน่วย cq อ่านความสูงได้เฉพาะกล่องที่สูงตายตัว** min-height ได้ 0
- **ระบบช่วยเล็งของมือถือ** (Chrome) ยกนิ้วที่แตะที่ว่างไปให้ของที่กดได้ใกล้สุด · กรอบต้องมีตัวรับการแตะ (React ใส่ `onclick` ให้เมื่อมี onClick) และปุ่มข้างในต้องให้นิ้วทะลุ ไม่งั้นระบบตัดกรอบทิ้ง
- **ResizeObserver ค่าเริ่มต้นดูแค่เนื้อใน** แถบที่หนาขึ้นจาก padding ไม่ถูกวัด ใช้ `box: "border-box"`
- **แอป Claude บน iPhone เปิด artifact แบบไม่เต็มจอก่อน แล้วสลับเต็มจอ** ใน 0.25 วินาที (สูง 799 เป็น 873 ขอบบน 0 เป็น 74) · `dvh` ในกรอบเท่าจอจริง
- **วัดก่อนเดาสาเหตุ** แคลร์บอกพี่กันว่าสาเหตุคือ dvh โดยไม่มีข้อมูลยืนยัน รอบถัดมาข้อมูลชี้ว่าผิด ต้องกลับไปแก้คำอธิบาย · หน้าทดลองรุ่นหลังจดค่าที่ใช้ยืนยันไว้ด้วย
- **ตัวจดของหน้าทดลองต้องวัดจากกรอบจริงตอนแตะ** รุ่นแรกเทียบกับตำแหน่งที่จดตอนเปิดหน้า ซึ่งเพี้ยนเมื่อหน้าเลื่อนหรือฟอนต์โหลดเสร็จทีหลัง

## สิ่งที่เรียนรู้

- **เส้นทางสุดท้ายของผู้เล่นคือตัวตั้ง ไม่ใช่ทางสั้นสุด** ด่านทางวนมีหลายเส้น เทียบกับทางสั้นสุดแล้วคนที่ไม่หลงเลยโดนหัก
- **คูณก่อนหาร** ตอนคิดเปอร์เซ็นต์ ไม่งั้นทศนิยมลอยปัดผิด (57.5 เป็น 57)
- **เมาส์ของส่วนเสริม Claude in Chrome ไม่ทำให้ปุ่มเข้าสถานะชี้ในแท็บหลัง** ทดสอบด้วยการจำลองคลาสกับตรวจลำดับความแรงของกฎ อย่าสรุปว่าพัง
- **วงคลื่นที่แผ่ออกนอกปุ่มโดนคอลัมน์ตัด** ต้องอยู่ในตัวปุ่ม
- **เซิร์ฟเวอร์ทดสอบในแท็บ Terminal ของแอปดับเมื่อ session ทำงานอื่น** เปิดผ่าน explorer เป็นหน้าต่างแยกแทน
- **แก้ฐานหลายแถวครั้งเดียว ตัวกันของระบบไม่ยอมจนกว่าพี่กันยืนยันในแชท** รอคำยืนยันก่อน
