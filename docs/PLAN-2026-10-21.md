## Context — ทำไมต้องทำ

เกม `maze-lab.html` (ไฟล์เดียว 967 บรรทัด อยู่ใน Downloads) ทำมาจาก Claude chat แล้วพี่กันเกลาต่อจนได้ระดับหนึ่ง
รอบตรวจ 21 ต.ค. 2569 เจอบั๊ก 7 ข้อ และพี่กันอยากบันทึกเกมที่เล่นจบลง Supabase โปรเจกต์ TB cal เพื่อเปิดดูย้อนได้

พี่กันสั่งในรอบนี้
- *"ตอนนี้เปลี่ยนเป้นเทคโนโลยีใหม่ให้ดีที่สุด เหมือนเว้บอื่นๆของเรา"* (3D ไว้คุยเรื่องหน้าตาทีหลัง ยังไม่ทำรอบนี้)
- แท็บห้องทดลอง **คงเป็น 2D เหมือนเดิม**
- บั๊กหัวข้อ 1 ทั้ง 7 ข้อ *"แก้ด้วยนะ"*
- ของที่เสนอในหัวข้อ 5 *"นอกนั้นทำมา"* ยกเว้นส่งด่านให้เพื่อน *"ไม่ส่ง"*
- ตารางกลุ่มวิธีบริหารยาที่ไม่ได้ล็อก *"ไปเขียนบอกในโปรเจคที่ใช้เจ้านั่น"* (เขียนบันทึก ไม่ใช่แก้)

ผลที่ต้องได้ — เกมเดิมหน้าตาเดิม แต่อยู่ในโปรเจกต์ Next.js แบบเว็บอื่น บั๊กหาย มีประวัติเกมกับตัวดูย้อน และพร้อมเปลี่ยนกระดานเป็น 3D ในรอบหน้าโดยไม่ต้องรื้อ

  - ช่อง: รหัส · `save_key` ห้ามซ้ำ (กันบันทึกซ้ำตอนเน็ตหลุด) · เวลาจบเกมจากเบราว์เซอร์ · เวลาสร้าง เวลาแก้ (ตัวดักฝั่งฐาน) · `deleted_at` · รุ่นแอป · ระดับ ขนาด วิธีสร้าง ทางหลอกขั้นต่ำ ทางวน ไฟฉาย · ผังกำแพงที่แพ็กแล้ว ตำแหน่งทางออก · บันทึกการเดินที่แพ็กแล้ว · เวลา ก้าว ทางสั้นสุด ทางแยก เลี้ยวผิด หลง ถอย เดินซ้ำ วาร์ป คะแนน · `replay_of` (เล่นซ้ำจากเกมไหน)
  - เปิด RLS ไม่ใส่กติกา (ตั้งใจ ตาม db-safety ข้อ 36) · ร่องรอยการแก้ด้วยตัวดักที่ฐาน
  - **แคลร์รันสร้างตารางผ่านตัวเชื่อม Supabase เมื่อถึงขั้นนี้** สร้างได้เฉพาะของที่ขึ้นต้น `mz_` ห้ามแตะตารางเดิม · รันแล้วเปิดผลตรวจของ Supabase ซ้ำ
- ฝั่งเซิร์ฟเวอร์ ยกจาก city-lab: `lib/supabaseAdmin.ts` (มี `import "server-only"` · รายชื่อตารางเขียนตายตัว) · `lib/server/cloudRows.ts` (จำกัดขนาดคำขอ · ตัวแปลงที่รับเฉพาะช่องที่อนุญาต · ทับแถวเดิมตาม `save_key`)
  - `POST /api/games` บันทึก · `GET /api/games` รายการแบบแบ่งหน้า (ระวังกับดัก 1,000 แถว) · `GET /api/games/[id]` เกมเดียวพร้อมผังกับบันทึกการเดิน

**4.3 ประตูรหัสผ่าน** ตามกฎของ city-lab *"ต้องมีประตูรหัสผ่านก่อนขึ้นเว็บจริง"* เพราะหลังบ้านถือกุญแจของฐานที่มีข้อมูลผู้ป่วย

## วิธีตรวจก่อนบอกว่าเสร็จ (สกิล testing-proof)

1. ชุดทดสอบตรรกะ `npm test`
   - ทั้ง 11 วิธีด้วยค่าตั้งต้น ทุกช่องไปถึงได้ ไม่มีวง
   - โหมดไม่มีทางวน ตรรกะใหม่ได้ตัวเลขเท่าตรรกะเดิมทุกตัว
   - โหมดทางวน ผลรวมที่มาของก้าวเกินตรงพอดี 200 ด่านต่อระดับ · เดินเส้นสั้นสุดอีกเส้นได้ 100
   - แพ็กแล้วแกะผังกับบันทึกการเดินได้ของเดิมเป๊ะ · เล่นซ้ำจากบันทึกได้สถิติเท่าตอนเล่นจริง
2. `npm run typecheck` · `npm run build` · `npm run cf:build` (OpenNext) ผ่าน
3. เปิดในเบราว์เซอร์ เล่นด่านกลางจนจบด้วยปุ่มลูกศร คีย์บอร์ด และลากนิ้ว → การ์ดขึ้น "เข้าระบบแล้ว" → อ่านแถวจริงในฐานด้วยตัวเชื่อม Supabase → เปิดประวัติ → ตัวดูย้อนเล่นจนจบได้สถิติตรงกัน · จุดแดงอยู่ตรงช่องที่เลี้ยวผิดจริง
4. เน็ตหลุด (ตั้งออฟไลน์) ตอนชนะ → ขึ้นว่ายังไม่เข้าระบบ → ต่อเน็ต → ส่งเองได้แถวเดียว
5. ประตู: ไม่ตั้งรหัส = 503 · ไม่มีบัตร = 401 · รหัสว่างเข้าไม่ได้ · `/api/games/x.png` ไม่ทะลุ
6. สลับแท็บกลางเกม 5 วินาที เวลาไม่เพิ่ม · ใบงานเปิดตัวอย่างก่อนพิมพ์แล้วดูไฟล์ PDF จริงว่าเป็น A4 สองหน้า
7. จอแคบ 375 จุด ไม่มีแถบเลื่อนแนวนอน · ธีมมืด · ซูมดูปุ่มลูกศร SVG
8. หลังสร้างตาราง เปิดผลตรวจของ Supabase ซ้ำ ต้องไม่มีอะไรใหม่นอกจาก "เปิด RLS ไม่มีกติกา" ของตาราง `mz_` ซึ่งตั้งใจ

## ขั้น 7 · ตรวจทานทั้งหมดอีกรอบหลังทำเสร็จ

พี่กันสั่ง *"ตอนที่ทำเสร้จเเล้ว ตรวจทายทั้งหมดอีกรอบ"* · ทำหลังขั้น 0 ถึง 6 และวิธีตรวจข้อ 1 ถึง 8 ผ่านหมดแล้ว เป็นรอบแยกต่างหาก

1. **เทียบกับเกมเดิมทีละความสามารถ** เปิด `docs/original/maze-lab.html` คู่กับเว็บใหม่ ไล่ตามเอกสารหัวข้อ 7 ถึง 10 ทุกบรรทัด
   - ห้องทดลอง: ปุ่มเลือก 11 วิธี · ตัวปรับของแต่ละวิธีกับปุ่มคืนค่า · ขนาด 5 ถึง 60 · แสดงทีละขั้นกับความเร็ว 5 ระดับ · ดูเฉลย · ปรับหลังสร้าง 5 ตัว · สถิติ 4 ช่อง · กราฟเทียบ 4 เรื่อง · คำอธิบายสีตามวิธี · ลดการเคลื่อนไหว
   - เกม: ระดับ 4 ระดับ · วิธีสร้างกับคำอธิบาย · ทางหลอกขั้นต่ำตามระดับ · ทางวน 5 ระดับ · ไฟฉาย · เสียงจำค่า · ปุ่มลูกศรกดค้างและเลื่อนนิ้วเปลี่ยนทิศ · คีย์บอร์ดตอนค้างแป้นไทย · ลากนิ้วบนกระดาน · เส้นหดตอนถอย · ธงกับวาร์ป · คะแนนกับคำประเมิน · การ์ดชนะและที่มาของก้าวเกิน · ช่องแดง · ยอมแพ้ · เสียง 7 แบบ · แอนิเมชันเฉลย · ธีมสว่างและมืด
   - ข้อความบนจอไม่มีขีดยาว ไม่มีจุลภาคในประโยคไทย ตรงกับเอกสารหัวข้อ 10
2. **อ่านโค้ดที่เขียนทั้งหมดซ้ำ** เทียบกับแผนนี้ทีละข้อ และเทียบกับสกิลที่ระบุไว้ท้ายแผนทีละรายการ (ไม่ใช่อ่านหาของผิดอย่างเดียว)
3. **รันวิธีตรวจข้อ 1 ถึง 8 ซ้ำทั้งชุดในรอบเดียว** บนเซิร์ฟเวอร์ที่สร้างใหม่สด
4. **อ่านเอกสารทุกไฟล์ซ้ำ** ว่าตรงกับโค้ดและฐานจริง (CLAUDE.md · README · spec · AUDIT ของเกม · ข้อ 32 ของ warfarin)
