## 1. ภาพรวม

- เป็นหน้าเว็บไฟล์เดียว (single file) ไม่มีไลบรารีภายนอก มีแค่ฟอนต์จาก Google Fonts
- มี 2 แท็บ
  - **ห้องทดลอง** ดูวิธีสร้างเขาวงกต 11 วิธีทำงานทีละขั้น ปรับนิสัยแต่ละวิธีได้ และเทียบสถิติทุกวิธี
  - **เล่นเกม** เดินออกจากเขาวงกตเอง จับเวลา ปักธง มีเสียง และให้คะแนนเต็ม 100

### เป้าหมายของเกม (สำคัญที่สุด อ่านก่อนแก้)

- เส้นทางที่วิ่งยาวๆ โดยไม่มีทางให้เลือกถือว่าน่าเบื่อ
- คะแนนต้องวัด **การตัดสินใจ** เป็นหลัก ไม่ใช่ระยะทาง

## 3. โมเดลข้อมูลเขาวงกต

### ตาราง

- กระดานขนาด `n × n` ช่อง
- ช่องมีหมายเลข `c = y * n + x` (x คือคอลัมน์ y คือแถว เริ่มที่ 0 มุมซ้ายบน)
- กำแพงเก็บใน `Uint8Array` 2 ชุด
  - `R[c] = 1` คือมีกำแพงด้านขวาของช่อง c
  - `B[c] = 1` คือมีกำแพงด้านล่างของช่อง c
- ขอบนอกกระดานวาดเสมอ ไม่เก็บในอาร์เรย์
- **ทางเข้า** คือช่อง `s = n >> 1` (แถวบนสุด คอลัมน์กลาง) ขอบบนของช่องนี้เปิด
- **ทางออก** คือช่อง `n*(n-1) + ex` ในแถวล่างสุด ค่าเริ่มคือ `ex = n >> 1` หรือถ้าเปิด "ย้ายทางออกไปจุดที่ไกลสุด" จะเลือกช่องแถวล่างที่ไกลจากทางเข้าที่สุด

### ฟังก์ชันพื้นฐาน

| ฟังก์ชัน | หน้าที่ |
|---|---|
| `neighbors(c,n)` | ช่องข้างเคียงทั้ง 4 ทิศที่อยู่ในกระดาน (ไม่สนกำแพง) |
| `openNb(c,n,R,B)` | ช่องข้างเคียงที่เดินไปได้จริง (ไม่มีกำแพงกั้น) |
| `carve(R,B,a,b)` | ทุบกำแพงระหว่าง a กับ b (ถ้า a < 0 ไม่ทำอะไร) |
| `wall(R,B,a,b)` | สร้างกำแพงระหว่าง a กับ b |
| `build(n,g)` | สร้าง R และ B จากผลของตัวสร้าง (อ่าน ops ชนิด `c` กับ `w`) |
| `solve(n,R,B,far)` | หาทางสั้นที่สุดด้วย BFS (การค้นแบบกระจายทีละชั้น) คืน `{path, ex}` โดย path เรียงจากทางออกย้อนไปทางเข้า |
| `deadEnds(n,R,B,ex)` | นับทางตัน (ช่องที่มีทางเปิดทางเดียว นับทางเข้าออกเป็นทางเปิดด้วย) |
| `countLoops(n,R,B)` | จำนวนวง = จำนวนช่องเปิด ลบ (n² − 1) ถ้าเป็นเขาวงกตสมบูรณ์จะได้ 0 |
| `countChoices(n,R,B,path,L)` | จำนวนทางหลอกยาวบนทางเฉลย (ดูหัวข้อ 6) |
| `shortStubs(n,R,B,L)` | จำนวนซอกตันสั้น (ดูหัวข้อ 6) |

### ผลลัพธ์ของตัวสร้าง (generator)

ทุกตัวสร้างคืน `{ ops, open?, walk? }`

- `ops` คือรายการขั้นตอน ใช้ทั้งสร้างกำแพงจริงและเล่นแอนิเมชัน
- `open: true` เฉพาะ Recursive Division (เริ่มจากกระดานโล่ง แล้วสร้างกำแพง)
- `walk` คือจำนวนก้าวที่ตัวเดินมั่ว (เฉพาะ Aldous-Broder กับ Wilson)

### รูปแบบ ops

| op | ความหมาย |
|---|---|
| `["c", a, b, adds?]` | ทุบกำแพง a กับ b แล้วตัวขุดไปอยู่ที่ b (`a = -1` แปลว่าแค่จุดเริ่ม) `adds` คือช่องที่เพิ่มเข้ารายการรอขุด (สีเหลือง) |
| `["m", c]` | ย้ายตัวขุดไปช่อง c (ถอยกลับ เดินมั่ว หรือกวาดทีละช่อง) |
| `["u", c]` | เอาช่อง c ออกจากรายการรอขุด |
| `["h", y]` | ไฮไลต์แถว y ที่กำลังกวาดหา (`-1` คือเลิกไฮไลต์) ใช้ใน Hunt-and-Kill |
| `["w", a, b]` | สร้างกำแพงระหว่าง a กับ b (Recursive Division และตัวเก็บกวาดซอก) |
| `["r", x, y, w, h]` | ไฮไลต์ห้องที่กำลังผ่า (`["r", -1]` คือเลิก) |
| `["wp", c]` | ต่อเส้นเดินมั่วไปช่อง c (Wilson) |
| `["wt", len]` | ตัดเส้นเดินมั่วเหลือยาว len (ลบวงที่เดินวนชนตัวเอง) |
| `["wx"]` | ล้างเส้นเดินมั่ว (หลังยืนยันเส้นทางแล้ว) |

## 4. วิธีสร้างทั้ง 11 วิธี และตัวปรับของแต่ละวิธี

ค่าตัวปรับเก็บใน `PDEF` (นิยาม) และ `PV` (ค่าปัจจุบันของแต่ละวิธี) ทุกวิธีมีปุ่มคืนค่าตั้งต้น

### กลุ่ม "ขุดทางยาว"

**DFS (การค้นแบบลงลึกก่อน) หรือ recursive backtracker**
- เดินสุ่มขุดไปเรื่อยๆ เจอทางตันก็ถอยกลับตามสแต็กไปหาจุดที่ยังแตกทางได้
- ตัวปรับ `straight` 0 ถึง 100 ค่าเริ่ม 50
  - 50 = สุ่มปกติ
  - มากกว่า 50 = มีโอกาส (s−50)/50 ที่จะเลือกเดินตรงไปทิศเดิม
  - น้อยกว่า 50 = มีโอกาส (50−s)/50 ที่จะบังคับเลี้ยว
  - ใช้ฟังก์ชัน `chooseDir`
- นิสัย ทางยาวคดเคี้ยว ทางตันน้อย ทางหลอกยาวน้อย

**Hunt-and-Kill (ล่าแล้วฆ่า)**
- ขุดแบบ DFS แต่เจอทางตันแล้วไม่ถอย ไปกวาดหาช่องที่ยังไม่ขุดที่ติดกับส่วนที่ขุดแล้ว
- ตัวปรับ `straight` (เหมือน DFS) และ `scan` = `row` (กวาดจากบนลงล่าง มีแถบสีฟ้าให้เห็น) หรือ `rand` (สุ่มจากทั่วกระดาน)

**Growing Tree (ต้นไม้ที่ค่อยๆ งอก)**
- เก็บรายการช่องที่ยังขุดต่อได้ (สีเหลือง) แต่ละรอบหยิบมาหนึ่งช่อง
- ตัวปรับ `pick` = `newest` `oldest` `middle` และ `mix` 0 ถึง 100% (โอกาสหยิบแบบสุ่มแทน) ค่าเริ่ม newest กับ 25%

### กลุ่ม "แตกกิ่งถี่"

**Prim (อัลกอริทึมของพริม)**
- สุ่มหยิบช่องที่อยู่ติดขอบส่วนที่ขุดแล้ว (frontier แปลว่าแนวหน้า) มาเชื่อม
- ตัวปรับ `start` = กลาง มุมซ้ายบน สุ่ม และ `dir` −100 ถึง 100 (น้ำหนักทางเชื่อมแนวนอน = 10^(dir/100))

**Kruskal (อัลกอริทึมของครุสกัล)**
- สุ่มทุบกำแพงทั่วกระดาน ยอมทุบเฉพาะกำแพงที่กั้นสองกลุ่มที่ยังไม่เชื่อมกัน ใช้ union-find (ระบบจับกลุ่ม)
- ตัวปรับ `dir` เปลี่ยนลำดับกำแพงด้วยคีย์สุ่ม × 4^(∓dir/100)
- แอนิเมชันระบายสีตามกลุ่ม (สีจาก hue = root × 137.508)

### กลุ่ม "สุ่มแบบยุติธรรม" (ทุกรูปแบบเขาวงกตมีโอกาสออกเท่ากัน)

**Aldous-Broder (อัลดัส บรอเดอร์)**
- เดินมั่วทั่วกระดาน ทุบกำแพงเฉพาะตอนเข้าช่องใหม่ ช่วงท้ายช้ามาก
- ตัวปรับ `switch` 10 ถึง 100% สลับไปใช้ Wilson เมื่อขุดได้เท่านี้ (100 = ไม่สลับ)

**Wilson (อัลกอริทึมของวิลสัน)**
- ต้นไม้เริ่มจากช่องเดียว ปล่อยตัวเดินมั่วจากช่องอื่นจนชนต้นไม้ ระหว่างทางถ้าวนชนรอยตัวเองจะลบวงทิ้ง (loop-erased random walk)
- ตัวปรับ `start` (จุดตั้งต้นต้นไม้) และ `order` = `rand` หรือ `scan`
- ฟังก์ชันแกนคือ `wilsonPhase` ใช้ร่วมกับ Aldous-Broder ตอนสลับ

### กลุ่ม "สร้างทีละแถว"

**Binary Tree (ต้นไม้ไบนารี)**
- ทุกช่องสุ่มทุบกำแพง 1 ใน 2 ทิศที่กำหนด
- ตัวปรับ `corner` = ne nw se sw และ `vert` 5 ถึง 95% (โอกาสทุบแนวตั้ง)
- นิสัยลำเอียงชัด สองขอบเป็นทางตรงโล่งยาว

**Sidewinder (ไซด์ไวน์เดอร์)**
- ทีละแถว ขุดไปทางขวาเป็นช่วง สุ่มปิดช่วง แล้วสุ่มหนึ่งช่องในช่วงทะลุไปแถวที่ทำแล้ว
- ตัวปรับ `close` 5 ถึง 95% และ `flip` = top หรือ bottom (ทางตรงยาวอยู่ขอบไหน)

**Eller (อัลกอริทึมของเอลเลอร์)**
- ทีละแถว จำแค่แถวเดียว สุ่มเชื่อมช่องต่างกลุ่ม ทุกกลุ่มต้องลงแถวล่างอย่างน้อยหนึ่งทาง แถวสุดท้ายรวมทุกกลุ่ม
- ตัวปรับ `join` 5 ถึง 95% และ `down` 0 ถึง 90% (โอกาสเปิดทางลงเพิ่ม)
- แอนิเมชันระบายสีตามกลุ่มเหมือน Kruskal

### กลุ่ม "สร้างกำแพงแทนการขุด"

**Recursive Division (แบ่งห้องซ้อนกัน)**
- เริ่มจากห้องโล่ง ผ่าห้องด้วยกำแพงพร้อมเจาะประตู แล้วผ่าห้องย่อยซ้ำ (ใช้สแต็ก ไม่ใช้ recursion จริง)
- ตัวปรับ
  - `room` 1 ถึง 8 หยุดผ่าเมื่อห้องเล็กกว่าหรือเท่ากับ room × room (1 = ผ่าจนสุด มากกว่า 1 จะเหลือห้องโล่งและเกิดวง)
  - `doors` 1 ถึง 3 ประตูต่อกำแพง (มากกว่า 1 จะเกิดวง)
  - `dir` −100 ถึง 100 ความเอียงของแนวผ่า
- เป็นวิธีเดียวที่ `open: true`

**ผลทดสอบ** ด้วยค่าตั้งต้นทุกวิธีให้ perfect maze (เขาวงกตสมบูรณ์ ทุกช่องไปถึงได้ และมีทางถูกทางเดียว) ยกเว้น Recursive Division ที่ตั้ง room มากกว่า 1 หรือ doors มากกว่า 1

## 5. การปรับหลังสร้างเสร็จ (ใช้ได้ทุกวิธี)

ลำดับการทำงาน คือ สร้าง → เก็บกวาดซอกสั้น → ทุบทางวน → หาทางเฉลย

### 5.1 เก็บกวาดซอกตันสั้น `cleanStubs(n,R,B,L)`

จุดประสงค์ ลดซอกตันสั้นที่มองแวบเดียวก็รู้ และเปลี่ยนเป็นทางหลอกยาว โดยเขาวงกตยังสมบูรณ์

ขั้นตอน
1. หาปลายทางตันทุกช่อง (ยกเว้นทางเข้าออก)
2. จากปลายตัน เดินย้อนตามทางจนเจอช่องที่มีทางเปิด 3 ทางขึ้นไป (จุดแยก j) เซลล์ที่เดินผ่านคือ "ซอก"
3. ถ้าซอกยาวไม่ถึง L ช่อง ให้หาช่องในซอกที่อยู่ติดกับ **ปลายตันของซอกอื่น** (ไม่ใช่ j ไม่ใช่ทางเข้าออก)
4. ถ้าเจอ ให้สร้างกำแพงตัดซอกออกจาก j แล้วทุบกำแพงไปเชื่อมกับปลายตันนั้น ซอกสองอันจึงรวมเป็นทางยาวอันเดียว
5. ทำซ้ำได้สูงสุด 8 รอบ หรือจนไม่มีอะไรเปลี่ยน

ข้อควรระวังที่เคยพัง
- ต้องเดินหาซอกใหม่ทุกครั้งก่อนย้าย เพราะการย้ายก่อนหน้าอาจทำให้ซอกเปลี่ยนรูป
- ต้องเชื่อมเฉพาะกับ **ปลายตัน** เท่านั้น เวอร์ชันแรกที่ยอมเชื่อมกับช่องใดก็ได้ทำให้เกิดวงและมีช่องหลุดออกจากกระดาน
- เวอร์ชันแรกที่นับซอกใหม่ทั้งกระดานทุกครั้งช้าเกินไป (ครึ่งวินาทีต่อด่านที่ 40 × 40)

ผลที่วัดได้ (40 × 40 ซอกสั้นกว่า 8 ช่อง)

| วิธี | ซอกสั้น ก่อน → หลัง | ทางหลอกยาวบนทางเฉลย |
|---|---|---|
| Kruskal | 493 → 105 | 40 |

### 5.2 ทางวน `braidOps(n,R,B,p)`

## 7. แท็บห้องทดลอง

### แผงควบคุม (เรียงจากบนลงล่าง)

### การควบคุม
- **ปุ่มลูกศรบนจอ** ทั้งกรอบเป็นพื้นที่กด เลือกทิศตามมุมจากจุดกลาง (ตรงกลาง 8px ไม่นับ) กดค้างเกิน 280 มิลลิวินาทีจะเดินต่อเนื่องทุก 110 มิลลิวินาที แตะค้างแล้วเลื่อนนิ้วเปลี่ยนทิศได้ ปุ่มใหญ่สำหรับนิ้วโป้ง (ผู้สร้างใช้วิธีนี้เป็นหลัก)
- **คีย์บอร์ด** ลูกศร หรือ W A S D ปักธง F กลับไปที่ธง R อ่านจาก `e.code` จึงใช้ได้แม้แป้นพิมพ์เป็นภาษาไทย ไม่รับปุ่มตอนกำลังพิมพ์ในช่องข้อความ
- **ลากนิ้วบนกระดาน** ตัวละครเดินตามเมื่อนิ้วอยู่ในโซนกลางของช่อง (ห่างจากกลางไม่เกิน 35%) อ้อมได้ไม่เกิน 2 ก้าว ถ้าไกลกว่านั้นเดินตรงเข้าหานิ้ว (กันนิ้วสั่นตรงแนวกำแพงแล้วก้าวงอก)
- เดินถอยกลับทางเดิม เส้นที่ลากไว้จะหดตาม
- เวลาเริ่มนับตอนก้าวแรก

### ธงและวาร์ป
- ปักได้ทีละ 1 ธง ปักใหม่ธงจะย้าย
- กลับไปที่ธง = วาร์ปทันที เส้นที่ลากกลับไปเป็นแบบตอนปักธง
- **วาร์ปไม่นับก้าว** (การตัดสินใจของผู้สร้าง) เหตุผล ผู้เล่นรู้ตัวและวางแผนปักธงไว้ล่วงหน้า ส่วนคนที่ไม่ปักธงต้องเดินกลับเองและนับก้าวจริง
- ก้าวที่เดินซ้ำช่วงที่เคยผ่านแล้วหลังวาร์ปยังนับ เพราะเดินจริง

### คะแนน (เต็ม 100)

```
D   = จำนวนทางเปิดที่ออกนอกทางเฉลย รวมทุกช่องบนทางเฉลย (ทางแยกที่ต้องตัดสินใจ)
W   = จำนวนครั้งที่เลี้ยวผิด (เดินจากช่องบนทางเฉลยไปช่องนอกทางเฉลย) ไม่เกิน D
dec = (D − W) / D
eff = min(1, ทางสั้นสุด ÷ ก้าวที่เดินจริง)
score = round(100 × (0.8 × dec + 0.2 × eff))
ถ้ามีก้าวเกินแม้แต่ก้าวเดียว คะแนนสูงสุดคือ 99
```

เหตุผล สูตรเดิม (ทางสั้นสุด ÷ ก้าวจริง) ลงโทษคนที่โดนทางหลอกยาว หนักเกินไป เลี้ยวผิด 2 ครั้งได้แค่ 69 ทั้งที่เกมตั้งใจทำทางหลอกให้ยาว สูตรใหม่หักเท่ากันทุกการเลี้ยวผิด ไม่ว่าจะหลงลึกแค่ไหน

คำประเมิน
- ไม่มีก้าวเกิน "เป๊ะ ไม่หลงเลยสักก้าว"
- W = 0 "ไม่เลี้ยวผิดเลย มีเดินถอยนิดหน่อย"
- W ≤ 2 "เกือบเป๊ะ เลี้ยวผิดนิดเดียว"
- W/D ≤ 0.15 "เก่งมาก"
- W/D ≤ 0.3 "พอใช้ หลงไปหลายทาง"
- มากกว่านั้น "หลงเยอะหน่อย ลองใหม่นะ"

### การ์ดตอนชนะ
- คะแนนตัวใหญ่ + แถบวัด + คำประเมิน + ป้าย "เวลาดีสุดใหม่"
- เวลา ก้าวทั้งหมด ทางแยกที่เลือกถูก (D−W / D) เลี้ยวผิดกี่ครั้ง
- แยกที่มาของก้าวเกิน ซึ่งรวมกันได้ตรงพอดีเสมอ
  - หลงในทางผิด `G.lost` (ก้าวที่ต้นทางหรือปลายทางอยู่นอกทางเฉลย)
  - ถอยหลังบนทางถูก `G.back` (ทั้งสองช่องอยู่บนทางเฉลย และถอยเข้าหาทางเข้า)
  - เดินซ้ำช่วงที่เคยผ่านแล้ว `G.rewalk` (เดินหน้าบนทางเฉลยแต่ยังไม่เกินจุดไกลสุดที่เคยไปถึง `G.maxP`)
  - วาร์ปกลับธงกี่ครั้ง (ไม่นับก้าว)
- ช่องที่หลงเข้าไปกลายเป็นสีแดงอ่อนหลังจบเกม
- ปุ่มเล่นด่านใหม่ และดูเฉลยเทียบ (กดสลับเปิดปิด)
- ตอนการ์ดขึ้น ปุ่มลูกศรกับปุ่มธงจะซ่อน

6. วาร์ปไม่นับก้าว (ดูหัวข้อ 8)
7. คะแนนเน้นการตัดสินใจ 80% ระยะทาง 20%

## 12. ข้อจำกัดที่รู้อยู่และไอเดียต่อยอด

- ยังไม่มี seed (รหัสสุ่ม) จึงเล่นด่านเดิมซ้ำหรือแชร์ด่านให้เพื่อนไม่ได้
- สถิติเก็บในเครื่องเดียว ไม่มีตารางคะแนนรวม
- ปักธงได้ทีละ 1 ธง
- DFS กับ Hunt-and-Kill เก็บกวาดซอกได้น้อย
- กระดานมีแค่ช่องสี่เหลี่ยม ยังไม่มีหกเหลี่ยม วงกลม หรือสามเหลี่ยม
- ยังไม่มีปุ่มพิมพ์ใบงาน (ต้นเรื่องคือใบงานเขาวงกต 40 × 40 สำหรับนักเรียน)
- ใช้ค่าตั้งต้นของแต่ละวิธีในเกม ยังปรับนิสัยรายวิธีในเกมไม่ได้
- Aldous-Broder ที่ 40 × 40 ใช้เวลาสร้างด่านนานกว่าวิธีอื่น (ราว 0.15 วินาทีต่อ 15 รอบ ยังรับได้)

## 13. วิธีทดสอบที่ใช้ระหว่างพัฒนา

- ดึงสคริปต์ก้อนที่ 1 ช่วง `const ALGOS` ถึงก่อน `const SPEED_LABEL` และช่วง `function neighbors` ถึงก่อน `function newMaze` ไปรันใน Node ได้ตรงๆ (ไม่แตะ DOM)
- ทดสอบทุกวิธีทุกค่าตัวปรับว่า ทุกช่องไปถึงได้ และ `countLoops = 0` (ยกเว้นกรณีที่ตั้งใจให้มีวง)
- ทดสอบ `solRun` ว่าทุกช่องมีเส้นไปถึง และจำนวนเส้นสีชมพู = ความยาวทางเฉลย − 1
- จำลองการเล่นด้วย Playwright เรียก `move()` `setFlag()` `backToFlag()` ตรงๆ แล้วตรวจว่า `G.lost + G.back + G.rewalk = ก้าวทั้งหมด − ทางสั้นสุด`
- ตอนเปิดไฟล์เดี่ยว ต้องมี CSS `[hidden]{display:none!important}` ไม่งั้นการ์ดชนะกับแท็บที่ซ่อนจะโผล่ (ไฟล์ที่ส่งให้ใส่ไว้แล้ว)
